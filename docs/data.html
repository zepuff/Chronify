Your data, and the rules that shape it

One folder holds everything. This page says what is in it, how the tracking rules work, and what to do when you update, move machine or walk away.

The one folder

Everything Chronify saves lives in ~/.work_tracker. There is no database server, no cloud, no account. Open it from ⏱ → 📁 Show my data folder, or from a terminal: 

open ~/.work_tracker

Copy that folder and you have copied everything: your hours, your notes, your settings and every status you ever wrote.

What each file is

FileWhat it holds
tracker.db The tracked time itself: every recorded stretch, the daily totals, and the archive of saved statuses. This is the file that matters most.
config.yaml The rules that turn windows into task names, and the timing defaults. Created on the first run and never touched by upgrades, so your edits survive.
profile.json Everything you typed into Settings. It wins over config.yaml wherever the two overlap.
projects.json Your projects, with their PeopleForce ids and rates.
settings.json The small running state: which project is active, which toggles are on, the current infrastructure line.
tasks.json What you logged under ✅ What I did today.
blockers.json Your open blockers.
reminders.json Your notes to self.
planner.json The plan for today, including what rolled over.
alerts.json Timed reminders: the text, the time, the weekdays.
history_export.md Rewritten every time you open 📝 Status history. Safe to delete.
my_invoice_template.docx Your own invoice template, once you connect one.

How a window becomes a task

Every five seconds Chronify notes the frontmost window as one string, app name — window title, and runs your rules against it. The first rule that matches wins, and its task name is what gets recorded.

The rules live at the bottom of config.yaml:

rules:
  - pattern: "(?i)(TASK-\\d+|[A-Z]+-\\d+)"
    task: "Ticket {1}"

  - pattern: "(?i)feature/([a-zA-Z0-9_-]+)"
    task: "Feature: {1}"

  - pattern: "(?i)jira|atlassian"
    task: "Jira"

  - pattern: "(?i)slack"
    task: "Meetings & Chat"

  - pattern: "(?i)github\\.com|gitlab\\.com"
    task: "Code Review / Git"

pattern is a regular expression and (?i) makes it ignore case. Anything you capture in brackets is available in the task name as {1}, {2} and so on, which is how a tab called TASK-482 · Fix the export dialog ends up recorded as Ticket TASK-482 rather than as Chrome.

Order matters, because the first match wins. Put your specific rules above the broad ones.

Anything that matches nothing is recorded under the app's own name, and apps listed under ignore_apps are never recorded at all.

After editing, press ⏱ → 🔄 Reload rules. There is no need to restart. The change applies to what is recorded from then on; time already logged keeps the names it was given.

A good habit: open 📊 Where today went after an hour of work. If the breakdown reads like your day, your rules are right. If everything is landing under one app name, a rule is missing.

What counts as working

The same file holds the timing. These are the defaults, and they are sensible enough that most people never touch them.

SettingDefaultWhat it does
poll_interval5 Seconds between checks of the frontmost window.
min_segment_seconds8 Shorter stretches are not stored, so flicking through tabs does not litter the log.
idle_threshold_seconds1500 Time without keyboard or mouse before it stops counting. Twenty-five minutes by default.
treat_media_as_activetrue Counts a real call as work even with no typing. A video left in the foreground does not qualify.
call_appszoom, meet, teams Apps that always count as an ongoing call.
call_apps_conditionalslack Apps that count only when the window title says so, which is how a Slack huddle is told apart from Slack.
alert_soundGlass Sound for timed reminders. Any file from /System/Library/Sounds, or empty for silence.

Backups

There is nothing clever to do. Copy the folder: 

cp -R ~/.work_tracker ~/Desktop/work_tracker-backup

If your home directory is already covered by Time Machine or a cloud drive, so is this. Restoring is the same move in reverse, with Chronify quit first.

Moving to another Mac

  1. Install Chronify on the new machine and start it once, so the folder exists.
  2. Quit it from ⏱ → Quit.
  3. Copy ~/.work_tracker across, replacing what is there.
  4. Start it again and grant Screen Recording on the new machine.

Your hours, projects, settings and statuses all come with you. The only thing that does not travel is the macOS permission, because that belongs to the machine.

Updating

brew update && brew upgrade chronify

Two things are worth knowing every time.

Screen Recording may need granting again. macOS ties the permission to the exact binary, and a new version is a new binary. Nothing warns you: the app keeps running and your task names quietly become app names. Check ⚙️ Settings → Screen Recording after an upgrade.

Quit and start it again. Homebrew replaces the files on disk, but the copy already running in memory is the old one until you restart it.

Your data folder is not touched by any of this. config.yaml keeps your edits, and profile.json keeps everything you typed into Settings.

Keeping data somewhere else

Set WORK_TRACKER_HOME and Chronify uses that folder instead of ~/.work_tracker. Useful for a second set of data, or for trying something out without touching the real one: 

WORK_TRACKER_HOME=~/scratch-tracker chronify

Everything moves together. There is no way to end up with the database in one place and the settings in another.

Uninstalling

brew services stop chronify
brew uninstall chronify

Your data folder stays where it is on purpose, so an uninstall can never take your hours with it. Once you are sure you want it gone: 

rm -rf ~/.work_tracker

That one is final. Take a copy first if there is any doubt.

What leaves the machine

Two things, both of which you ask for by name.

  • Hours and status text you push to PeopleForce, when you press 📤 Send hours to PeopleForce or turn on the nightly auto-push. Only projects that carry a PeopleForce id are ever sent.
  • A model download, once, if you choose Ollama as the writer of your daily status. After that it runs on your machine and your notes stay there.

Window titles, tracked hours, notes, plans and statuses are never sent anywhere else. There is no telemetry and no account, which is also why there is nobody to ask for your data back.
